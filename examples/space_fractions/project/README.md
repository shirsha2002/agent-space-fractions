# Space Fractions

A desktop educational game for practicing sixth-grade fraction concepts. Built with Python's standard library (Tkinter, sqlite3, fractions, hashlib, secrets).

## Features

- Animated, skippable intro with starfield
- Main menu with Play, Help, Score History, and Admin Panel (for admins)
- 10 original fraction questions with explanations
- One point per correct answer, no duplicate scoring
- Pause/resume, next question, restart, and ending feedback
- Score persistence in SQLite
- Admin panel to edit questions
- Local user accounts with PBKDF2 password hashing
- First-run admin password setup (admin cannot login until password is set)
- Player registration for new accounts
- Dark space theme with Canvas-drawn stars and planets

## Requirements

- Python 3.13 (standard library only)
- Windows, macOS, or Linux with a display

No external packages are required.

## Launch

Run from the project root:

```
python main.py
```

## Tests

Run tests from the project root:

```
python -m unittest discover -s tests
```

## Persistence

Data is stored in a SQLite database in a per-user writable application data folder:

- Windows: `%APPDATA%\SpaceFractions\space_fractions.db`
- Linux/macOS: `~/.local/share/SpaceFractions/space_fractions.db`

## First-Run Admin Setup

On first launch, an `admin` user is created but cannot authenticate because no password is set. To set the initial admin password, click "First time? Set up admin password" on the login screen and enter a password of at least 8 characters. After that, log in as `admin` with the chosen password.

## Roles

- **User**: Can register, login, play the game, view own score history, and view help.
- **Admin**: In addition to user capabilities, can edit questions via the Admin Panel. Admin account cannot be used until password is set.

## Assumptions and Deviations

The original architecture documents specified a web-based microservices deployment with cloud infrastructure, OAuth2, PostgreSQL, Redis, etc. This desktop implementation is a **provisional local adaptation**. It does **not** implement any cloud services, OAuth2, or production scalability features. The local roles are simple username/password authentication with PBKDF2 hashing; they are not OAuth2.

## API Contracts

The core game API is stable and defined in `game_core.py`:

- `Question(qid, prompt, options, answer, explanation='')` with `check(answer_string) -> bool`.
- `Game(questions)` with `submit`, `next_question`, `pause`, `resume`, `restart`, and state strings `playing`, `paused`, `game_over`.

These contracts are tested independently in `tests/test_game.py`.

## Test Notes

The generated tests are model-authored and cover core game logic, storage validation, and role authorization. An independent host agent may supply additional contract checks.


## Generation and reviewed changes

The complete initial project was generated by official deepseek-v4-pro from the
two supplied architecture inputs, followed by two bounded model repair calls.
All three original model manifests are retained in the host provenance package.
The model-only last round had one incorrect test vector and remaining local
authorization/UI edge cases. Codex made a disclosed reviewed patch without any
additional model calls: authenticated storage updates/password changes, support
for textual distractors, a genuinely invalid transaction-preservation test vector,
UI binding/pause cleanup, automatic intro ending with original Canvas planet art,
recent score ordering and additional operator-authored regression checks.
This is a DeepSeek-generated project with reviewed operator adjustments, not a
claim of perfect autonomous generation. Host contract checks are independent of
the generated tests. No production OAuth2/cloud/security-sandbox claim is made.

Player: choose Register New Player, use a local username and password of at least
eight characters, then log in. Administrator: choose first-time admin setup once,
choose your own password, then log in as admin. No working default password is
shipped. Questions and scores are local to this Windows user. The low-level SQLite
file is not protected against the Windows account owner directly modifying it.
